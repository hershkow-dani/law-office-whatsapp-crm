# מערכת CRM למשרדי עורכי דין — WhatsApp

מערכת CRM שמאפשרת ללקוח לנהל שיחה טבעית ב-WhatsApp מול המשרד, בזמן שמאחורי הקלעים המערכת שומרת את
הגדרות המשרד, ממירה את השיחה לשדות וסטטוסים, מחליטה מתי לענות אוטומטית ומתי להעביר לאדם, ומאפשרת ניהול
תיקים, משימות, מסמכים ודוחות — הכל ללא תלות במספר מרכזי של ספק כלשהו.

## מצב נוכחי

- ✅ **שלב א׳** — הגדרות זהות/מדיניות משרד, חיבור מספר WhatsApp (קיים או ייעודי)
- ✅ **שלב ב׳** — מנוע שיחה (מדומה), חילוץ שדות, תיקים ומשימות, דוחות וניקוד
- ✅ **שלב ג׳** — תבניות מסמכים ויצירת מסמכים ממולאים אוטומטית
- ✅ **שכבת Webhook** — מוכנה ובדוקה, ממתינה רק להזנת טוקנים אמיתיים מ-Meta
- ✅ **התחברות והרשאות** — כל משרד עם חשבונות משתמש משלו (בעלים/צוות), כל הנתונים מבודדים בין משרדים
- ✅ **איפוס סיסמה עצמאי** — זרימה מלאה, ממתינה רק לחשבון שירות מייל אמיתי
- ✅ **פריסה מוכנה (Docker)** — Dockerfile ל-server/client + docker-compose; **נבדק בפועל** עם `docker
  compose build` ו-`up` אמיתיים — שני האימג׳ים נבנים, שני הקונטיינרים עולים, ה-nginx מגיש את הלקוח
  ומעביר `/api/...` לקונטיינר השרת דרך הרשת הפנימית, ונבדק flow מלא (הרשמה + session + טעינת האפליקציה
  בדפדפן) — ראו [פריסה](#פריסה-deployment) למטה
- ⏳ **חיבור WhatsApp חי** — טרם בוצע; ראו [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#מה-נדרש-לחיבור-whatsapp-חי-עדיין-חסר) למה בדיוק חסר

## הרצה מהירה

```bash
# טרמינל 1 — שרת
cd server
npm install
npm run build && npm start

# טרמינל 2 — לקוח
npm install
npm run dev
```

הלקוח עולה על `http://localhost:5173`, השרת על `http://localhost:3001`.

## בדיקות

```bash
cd server
npm test
```

## פריסה (Deployment)

הפרויקט כולל Dockerfile ל-`server/` ול-לקוח (root, מוגש דרך nginx), ו-`docker-compose.yml` שמחבר
ביניהם. ה-nginx בקונטיינר הלקוח מגיש את הקבצים הסטטיים **ומעביר** (`proxy_pass`) כל בקשת `/api/...` אל
קונטיינר השרת — כך שמנקודת המבט של הדפדפן הכל על אותו origin, בדיוק כמו ה-proxy של Vite בפיתוח, ועוגיית
ה-session פשוט עובדת בלי צורך בהגדרות CORS.

**✅ נבדק בפועל** — הותקן Docker Desktop (עם WSL2), הורץ `docker compose build` אמיתי (שני האימג׳ים
נבנו בהצלחה) ואז `docker compose up` אמיתי: שני הקונטיינרים עלו, ה-healthcheck עבר, ונבדקו מהדפדפן
`GET /api/health`, `POST /api/auth/register` מלא (כולל session cookie ששרד בקשה הבאה דרך `/api/auth/me`),
וטעינת עמוד ה-login בעברית/RTL — הכל דרך הפורט החיצוני היחיד (8080), בדיוק כמו שיהיה בפריסה אמיתית.

```bash
cp .env.example .env
# ערכו את .env — לפחות SESSION_SECRET (למשל: openssl rand -hex 32)

docker compose up -d --build
# הלקוח על http://localhost:8080, השרת פנימי בלבד (לא חשוף כברירת מחדל)
```

הנתונים (SQLite) נשמרים ב-volume בשם `crm-data` ושורדים `docker compose down`/`up` חוזר (לא `-v`).

**זה עדיין לא "פריסה לשרת אמיתי"** — זו הכנה שרצה בכל מכונה עם Docker. כדי להעלות בפועל צריך גם:
פלטפורמת אירוח (VPS / Railway / Render / DigitalOcean וכו'), דומיין + תעודת HTTPS, ולפתוח את פורט 8080
(או להעמיד reverse proxy נוסף מולו) — אלה החלטות שדורשות בחירת ספק וחשבון, ולכן נשארו בחוץ בשלב הזה.

לפרטים מלאים — החלטות ארכיטקטורה, מבנה ה-API, מנועי ההחלטה/חילוץ/ניקוד, ומה בדיוק חסר לחיבור WhatsApp
חי — ראו **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.
